A duka project is called a **kao**.

<FileTree>

    - project_name/
        - kao.toml
        - src/
            - *.duka
        - build/
            - *.dukac
        - modules/
            - ...
        - test/
            - *.test.duka

</FileTree>

`kao.toml` is the manifest, `src/main.duka` is the entry. See
[modules](/language/modules/).

## Init

```sh
dukao init <path> --name --version --force
```

- `<path>` optional, `./` in default
- `--name`, uses directory name in default
- `--version`, `0.1.0` in default
- `--force`, replace an existing kao

## Run

```sh
dukao run <path> --entry --no-color -- <script args>
```

- `<path>` optional, nearest `kao.toml` upward, else `./`
- `--entry` sets the entry file explicitly
- everything after `--` goes to `...` of the script

## Check

```sh
dukao check <path> -f <file>
```

- `<path>` optional, nearest `kao.toml` upward, else `./`, if `-f` is empty, it checks **all files** in this kao (if found).
- `-f` or `--file` checks only **single file** with kao config from `<path>` (if provided).

## Build

```sh
dukao build <path> --list
```

- `--list` only lists the files that would be built

## Test

```sh
dukao test <path> --list --filter <name> --no-color
```

Tests are `.duka` files under `test/`. `tests/` in the repo has examples, run
them with `dukao test ./tests`.

## Dependencies

```sh
dukao add <git url> [--tag v1.0] [--branch main] [--version "^1.2"] [--as <name>]
dukao add <dir> --path [--as <name>]
dukao remove <name>
dukao install            # install what the lock records, resolving what it misses
dukao install --frozen   # fail instead of resolving; the lock must cover the manifest
dukao install --offline  # never touch the network, use the cache only
dukao update             # re-resolve everything and rewrite kao.lock.toml
```

`add` writes into `[dependencies]` of `kao.toml`, `install` resolves them into
`modules/` and pins them in `kao.lock.toml`. `install` keeps the commits the lock
records; `update` is what moves a `version` range or a branch forward.
`--frozen` installs exactly what the lock records and refuses a lock that does
not cover the manifest. Packages removed from the manifest are pruned from
`modules/`, and path dependencies are recorded relative to the project so the
lock travels with a checkout.

## Serve

```sh
dukao serve <path> --port
```

Serves `build/` on `3000` in default, which is where the wasm target lands.
